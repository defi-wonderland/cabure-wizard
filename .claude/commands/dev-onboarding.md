Walk a TypeScript developer through Caburé onboarding. This is designed for a new implementation contributor, but it works for anyone who will edit the monorepo or generated ceremony app.

Read `.claude/CLAUDE.md` first, then guide the developer through these steps:

## 1. Project Overview

Explain Caburé in 3 sentences:
- It is a Groth16 Phase 2 trusted setup toolkit that replaces p0tion + DefinitelySetup.
- Operators run `npx @wonderland/create-cabure-ceremony` to scaffold a deployable ceremony app.
- Contributors participate through the generated browser UI or the headless `cabure` CLI.

## 2. Monorepo Tour

Walk through the repository structure:
- `packages/create-cabure-ceremony` — zero-runtime-dependency Node wizard. Important modules: `src/prompts.ts`, `src/validate.ts`, `src/circuits.ts`, `src/scaffold.ts`, `src/index.ts`.
- `packages/create-cabure-ceremony/templates` — the generated Next.js 15 app. Most ceremony behavior changes happen here.
- `packages/crypto` — `@wonderland/cabure-crypto`, the published crypto package with ESM/CJS/worker builds.
- `packages/cli` — `@wonderland/cabure-cli`, the headless contributor CLI with `cabure status` and `cabure contribute`.

Mention the root workflow:
```bash
pnpm install
pnpm format
pnpm build
pnpm test
pnpm test:e2e
```

## 3. Generated App Architecture

Walk through the generated app as a single Next.js application:
- `src/app/screens/` — participant flow: Landing, Entropy, Tier, Progress, Complete, Verify.
- `src/app/api/ceremony/` — queue, status, zkey, upload, contribute, receipts, participant eligibility, CLI auth.
- `src/app/api/auth/[...nextauth]/` — GitHub OAuth via NextAuth.
- `src/hooks/` — browser state and contribution orchestration.
- `src/lib/` — Vercel Blob, Upstash KV, auth, ceremony state, worker client, environment loading.
- `src/middleware.ts` — protects queue, participant, contribute, and upload routes.

Emphasize: there is no separate `coordinator/` and no IPFS-first architecture. Generated ceremonies deploy as one Vercel-oriented Next.js app using Vercel Blob for zkeys and Upstash Redis/Vercel KV for state, queues, receipts, and locks.

## 4. Implementation Rules

Walk through decisions the developer must preserve:
- Package names are `@wonderland/create-cabure-ceremony`, `@wonderland/cabure-crypto`, and `@wonderland/cabure-cli`.
- The wizard asks exactly 4 questions: project name, target contributions, optional end date, optional circuit artifacts path.
- Target contributions default to 100 when Enter is pressed.
- Do not add a ptau prompt. Operators run `npm run setup:ptau` in the generated app.
- Always generate `circuits/`; copy discovered `.r1cs` files when a circuit path is provided.
- `ceremony.config.ts` is generated by `src/scaffold.ts` and is the primary config surface.
- Tiers are auto-generated from discovered circuits, not chosen interactively by the operator.
- Browser crypto runs in a Web Worker through `@wonderland/cabure-crypto/worker`.
- Entropy requires mouse/click input; CSPRNG alone is not enough.
- Chain hash format is `${previousChainHash}:${contributionHash}:${participantId}:${timestamp}`.
- Genesis previous hash is `0x` plus 64 zeros.

## 6. Getting Started

Suggest a first step based on the developer's focus:
- Wizard prompt or validation work: start in `packages/create-cabure-ceremony/src/prompts.ts` and `src/validate.ts`, then update tests in `src/__tests__/`.
- Generated app behavior: edit `packages/create-cabure-ceremony/templates`, then run wizard e2e tests.
- Storage/API work: inspect `templates/src/lib/ceremony-state.ts`, `kv-store.ts`, `blob-store.ts`, and relevant `templates/src/app/api/ceremony/**/route.ts`.
- Crypto work: inspect `packages/crypto/src` and run the crypto package tests.
- CLI work: inspect `packages/cli/src/commands`, `auth.ts`, and `client.ts`.
